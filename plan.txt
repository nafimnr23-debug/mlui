Plan: Universal ML Inference Web Platform with Admin Widget Builder

1. Foundation and Authentication

Set up Bolt Database auth with email/password login
Define two roles: user and admin via a profiles table
Create the database schema: projects, images, inference_results, widget_layouts, button_configs, user_project_access
Home screen showing project cards as thumbnails with project name and last-used date
Clicking a card enters the project workspace; admins also see a "Manage Projects" entry point
2. Database and Storage Schema

Projects table: id, name, description, created_by, model_folder_path, python_entry_script
Images table: id, project_id, user_id, filename, storage_path, status (pending / inferenced)
Inference results table: id, image_id, json_data (JSONB), edited_json_data (JSONB), created_at
Widget layouts table: id, project_id, layout_config (JSONB storing widget positions, sizes, types)
Button configs table: id, project_id, label, json_key, action_type, action_script, visual_config (colors, size)
All image files stored in Bolt Database Storage, one bucket per project
3. Project Workspace — Core Layout Engine

The workspace renders a free-form canvas divided into a dot-grid (like button_example.jpeg)
Users see the saved layout; admins can toggle "Edit Layout Mode" (Ctrl+M or configurable hotkey)
In Edit Layout Mode, a left sidebar shows draggable widget types: File Manager, Image Preview, Button Panel, Console
Widgets snap to grid, cannot overlap (collision detection on drop)
Each widget is independently resizable by dragging corners
Layout config is saved as JSON per project in the widget_layouts table
Button panels can be placed above, below, left, or right of the preview widget
4. File Manager Widget

Shows all images uploaded to this project by the current user
Green border on thumbnail = inference JSON exists; red border = no JSON yet
Ctrl+Click for multi-select; checkboxes appear on hover
Sort by name, date, status
"Select Folder" to batch-upload multiple images
Refresh button to re-sync with storage
Summary bar showing X images, Y with JSON, Z missing
5. Image Preview and Contour Editor Widget

Canvas-based viewer using HTML5 Canvas or a lightweight canvas library
Loads the selected image; overlays contours, keypoints, mandible, maxilla from the JSON
Each JSON layer (Mandible, Maxilla, Contours, Keypoints, Left Edge, Right Edge, Bone Points, Loss %) is toggled by its corresponding button
Clicking a button highlights just that contour/layer on the canvas
Edit mode: draggable control points on the active contour path
Save button writes edited contour coordinates back to the inference_results table (edited_json_data column)
Discard button reverts to original inference JSON
Zoom/pan controls; Ctrl+Scroll to zoom
6. Button System — User Side

Buttons are rendered inside a Button Panel widget
Each button has: display label, associated JSON key, action type (highlight layer, edit contour, save, discard, export)
Visual state: active/inactive/disabled, custom background and text color
Buttons arranged in a configurable grid layout within the panel widget
Clicking a button fires the associated action via a central event bus
7. Admin — Project Creation and Management

Admin-only route /admin with a "New Project" form: name, description
Creating a project creates a server-side folder for that project and initializes a Python venv
Admin can upload Python model files and a requirements.txt via a file browser UI
Terminal panel (read-only output stream) shows pip install progress and script output
File manager panel for the project folder: view directory tree, upload files, delete, rename, copy — a mini online IDE
"Run Inference" triggers the project's Python script on selected images, streams stdout/stderr to the console widget
Inference output JSON is parsed and saved to the inference_results table
8. Admin — Widget Layout Editor

Full-screen dot-grid canvas, similar to the Steam Deck controller layout editor in button_example.jpeg
Left sidebar lists available widgets to drag onto the canvas
Placed widgets show resize handles and a settings gear icon
Widgets cannot overlap (pushed apart or rejected on collision)
"Save Layout" stores the config; this becomes the default layout for all users of that project
Users can reset to the admin-defined default or save a personal override
9. Admin — Button Builder and JSON Key Importer

"Import from JSON" workflow: admin uploads or pastes a sample JSON file
The system parses all top-level and nested keys and presents them as a list
Admin checks which keys should become buttons
For each selected key, a button config form opens: display label (can differ from key name), action type, action script (a small JS snippet or predefined action), button color, text color, position in the button panel grid
"Add New Button" manually creates a button from scratch with the same form
Saved buttons are stored in button_configs and rendered in the project workspace
10. Python Backend and Server-Side Execution

A lightweight Node.js (Express) or Python (FastAPI) backend service handles process execution — this runs alongside the React frontend in deployment
API endpoints: POST /api/inference/run, GET /api/inference/status/:jobId, POST /api/project/install-deps, GET /api/files/list/:projectId, POST /api/files/upload, DELETE /api/files/:path
Each project gets its own folder: /projects/{project_id}/model/, /projects/{project_id}/venv/
Job queue handles concurrent inference requests (per your "multiple users at once" concern — queue with job IDs, websocket or polling for status)
Bolt Database Edge Functions proxy authenticated frontend requests to this backend
The database abstraction layer uses an adapter pattern so swapping Bolt Database for MongoDB only requires changing the adapter, not the business logic
11. Export, Sharing, and User Data Persistence

"Export JSON" button downloads the current (edited or original) inference JSON for the selected image
Users can share a project link — recipients with accounts can view images and JSONs in read-only mode
Inference history per image: each save creates a new version row so edits are non-destructive
User preferences (widget layout overrides, hotkey settings) stored per user per project
Summary of Approach

This builds in three layers: the React frontend (Bolt/Vite) handles the visual canvas, widget system, and contour editing; Bolt Database handles auth, storage, and the relational data; a Node.js or FastAPI backend handles all Python process management and file system operations. The adapter pattern on the data layer means MongoDB can replace Bolt Database Postgres with minimal refactoring. The widget system is the most novel piece — it uses a dot-grid collision system similar to what you showed in button_example.jpeg, giving admins complete control over layout without any hardcoded panel positions.

Before I proceed — three clarifying questions:

For the Python execution backend, do you have a server/VPS where this will be deployed, or do you need it to work entirely within a serverless environment like Bolt Database Edge Functions? (This affects whether we can actually spawn Python processes.)

For the contour editor, should users be able to add or delete points on a contour path, or only move existing points? The JSON shows very dense point arrays (hundreds of coordinates per tooth).

Should multiple users be able to run inference simultaneously and each get their own results stored separately, or does one inference result per image serve all users on that project?
